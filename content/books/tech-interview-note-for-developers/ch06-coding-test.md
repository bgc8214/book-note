## 핵심 아이디어

코딩 테스트는 난해한 문제를 푸는 시험이 아니라 기본 개념으로 문제를 해결할 수 있는지
보는 절차다. 그래서 다 풀었는지보다 어떤 자료구조를 왜 골랐는지가 평가 대상이 되고,
통과한 뒤 면접에서 그 선택을 되묻는다. 설명할 수 없는 풀이는 내 것이 아니다.

## 요점

- 실무와 관계없는 난해한 문제는 출제 의도에 어긋나며 대부분 중·하 수준으로 충분하다.
- 코딩 테스트용으로는 파이썬과 자바스크립트가 간결하지만, 지원 회사가 쓰는 언어로 연습하는 편이 유리하다. 언어를 자바로 제한하는 회사도 있다.
- 다 푸는 것이 정답이 아니라 작성 흐름과 선택한 자료구조가 핵심이며, 통과 후 면접에서 왜 그렇게 풀었는지 리뷰한다.
- 실력이 아니라 시간 배분을 못 맞춰 떨어지는 지원자가 많다.
- 기초 훈련 다음 단계는 실행 속도다. 같은 크기의 배열도 접근 방식에 따라 수행 시간이 크게 갈린다.
- 실제 시험에서 접한 문제를 온라인에 공유하면 페널티를 받을 수 있다.

## 실천 아이템

- [ ] 지원할 회사가 코딩 테스트 언어를 제한하는지 먼저 확인하고 그 언어로 연습한다.
- [ ] 하루 한두 문제씩 100일 챌린지로 풀고 매일 깃에 올려 잔디와 TIL을 함께 남긴다.
- [ ] 4~5명 스터디를 꾸려 각자 다른 문제를 리뷰한다. 5일치를 주말에 네 명이 나눠 리뷰하면 한 주에 20문제가 자기 것이 된다.
- [ ] 푼 문제마다 "왜 이 자료구조를 썼는가, 더 나은 방법은 없는가"를 스스로 묻고 답을 적어둔다.
- [ ] 시간이 부족해 못 푼 문제는 비워두지 말고 풀이 방향을 주석이나 의사코드로 제출한다.

## 용어

스택 (stack)
: 후입선출(LIFO) 구조. 마지막에 삽입된 데이터가 먼저 제거된다. 웹 브라우저의 뒤로 가기, 함수 호출 스택이 예다.

큐 (queue)
: 선입선출(FIFO) 구조. 먼저 삽입된 데이터가 먼저 제거된다. 프린터 대기열, 메시지 큐가 예다.

시간 복잡도 (time complexity)
: 입력 크기가 커질 때 실행 시간이 늘어나는 정도. 코딩 테스트 채점의 주요 기준이다.

빅오 표기법 (Big-O notation)
: 시간 복잡도를 나타내는 표기. O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) 순으로 커진다.

의사코드 (pseudocode)
: 실제 문법 대신 논리 흐름만 서술한 코드. 시간이 부족할 때 풀이 방향을 전달하는 수단으로 쓴다.
