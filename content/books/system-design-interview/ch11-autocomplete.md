## 핵심 아이디어

자동 완성은 대량의 데이터를 계속 수집·처리해 사용자가 조회할 작은 데이터 구조로 줄이는
시스템의 전형이다. 핵심 설계 판단은 전처리와 쿼리를 떼어 놓는 것이다. 둘은 성격이 전혀 달라
독립적으로 개발하고 확장해야 한다.

## 요점

- 자동 완성은 대량 데이터를 지속적으로 수집·처리해 수 메가바이트 수준의 데이터 구조로 만드는 분산 시스템의 예다.
- 검색과 겹치는 부분이 있지만 목적이 다르다. 검색은 문서를 찾고, 자동 완성은 사용자가 입력하려는 내용을 제안한다.
- 전처리가 많은 시스템이므로 전처리와 쿼리를 별도 구성 요소로 나눠 독립적으로 개발하고 확장한다.
- 검색 서비스와 로깅 서비스가 기록한 검색 문자열을 자동 완성의 입력으로 쓸 수 있다.
- 가중치 트라이를 쓴다. 조회가 빠르고 저장소 요구가 낮다.
- 대규모 집계 작업은 여러 단계로 나눠 저장·처리 비용을 줄인다. 대가는 높은 복잡성과 유지보수 부담이다.

## 용어

타입어헤드 (typeahead)
: 사용자가 입력하는 동안 키 입력마다 제안 목록을 반환하는 기능. 자동 완성의 다른 이름이다.

가중치 트라이 (weighted trie)
: 문자열을 문자 단위로 분기 저장하고 각 노드에 가중치를 붙인 자료구조. 조회가 빠르고 저장소를 적게 쓴다.
