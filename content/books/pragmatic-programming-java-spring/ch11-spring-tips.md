## 핵심 아이디어

스프링을 쓰면서도 의외로 모르고 넘어가는 동작들이 있다. 의존성 주입이 타입을 기준으로
움직인다는 사실과, 같은 클래스 안에서의 자가 호출이 프록시를 우회한다는 사실이 대표적이다.
둘 다 모르면 원인을 못 찾는 버그로 돌아온다.

## 요점

- 스프링의 의존성 주입은 타입을 기반으로 동작한다. 컨테이너는 타입으로 빈을 찾는다.
- 일치하는 타입의 빈을 찾지 못하면 예외가 발생한다. 어떤 예외인지 알아야 원인을 짚을 수 있다.
- 같은 클래스 안에서 메서드를 직접 호출하는 자가 호출은 프록시를 거치지 않는다.
- 그래서 자가 호출에서는 트랜잭션 같은 프록시 기반 기능이 걸리지 않는다.

## 실천 아이템

- [ ] 같은 클래스 안에서 트랜잭션 메서드를 직접 호출하는 코드가 있는지 찾는다.
- [ ] 같은 타입의 빈이 여럿일 때의 주입 전략을 미리 정해둔다.

## 용어

타입 기반 주입
: 스프링 컨테이너가 이름이 아니라 타입으로 빈을 찾아 주입하는 방식.

자가 호출 (self invocation)
: 같은 객체 안에서 자기 메서드를 직접 호출하는 것. 프록시를 우회하므로 AOP 기능이 적용되지 않는다.
