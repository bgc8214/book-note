## 핵심 아이디어

객체지향을 이해하려면 절차지향을 먼저 알아야 한다. 대부분의 개발자가 절차지향이 무엇인지
모른 채 객체지향을 말하기 때문이다. 자바는 객체지향 언어지만 자바로 쓴 코드가 절차지향일
수 있다. 언어가 패러다임을 보장하지 않는다.

## 요점

- 대부분의 개발자는 절차지향이 무엇인지 모른 채 객체지향을 이야기한다.
- 순차지향과 절차지향은 다른 패러다임이다. 코드가 위에서 아래로 실행된다는 설명만으로는 둘을 구분할 수 없다.
- 자바를 쓰면서도 절차지향적인 코드가 나올 수 있다. 문법이 아니라 데이터와 행동이 어디 있는지가 패러다임을 가른다.
- 객체지향의 중심에는 책임과 역할이 있다.
- 묻지 말고 시켜라(TDA) 원칙은 수동적인 객체를 능동적인 객체로 바꾼다.

## 실천 아이템

- [ ] getter로 데이터를 꺼내 바깥에서 판단하는 코드를 찾아, 그 판단을 객체 안으로 옮긴다.
- [ ] 클래스를 새로 만들 때 이 객체의 책임과 역할을 한 문장으로 먼저 적는다.

## 용어

절차지향 (procedural programming)
: 데이터와 프로시저를 분리하고 프로시저의 호출 순서로 프로그램을 구성하는 패러다임.

순차지향 (sequential programming)
: 절차지향 이전의 패러다임. 코드가 순서대로 실행되는 것만으로 설명되지 않는다.

TDA 원칙 (Tell, Don't Ask)
: 객체에게 데이터를 묻지 말고 일을 시키라는 원칙. 속성을 이미 가진 객체를 능동적으로 만드는 데 쓴다.
