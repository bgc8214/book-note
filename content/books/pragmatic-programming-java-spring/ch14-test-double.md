## 핵심 아이디어

테스트 대역의 "대역"은 대역폭이 아니라 영화의 스턴트맨, 그 대역이다. 오직 테스트를 위해
만들어진 진짜가 아닌 객체들이고, 종류가 다섯으로 갈린다. 어느 것을 쓰느냐는 상태를 검증할
것인지 행위를 검증할 것인지에 따라 정해진다.

## 요점

- 테스트 대역은 오직 테스트를 위해 만들어진 가짜 객체나 컴포넌트다. 대역폭이 아니라 스턴트맨의 대역이다.
- 종류는 더미, 스텁, 페이크, 목, 스파이 다섯이다.
- 목은 행위 기반 검증에, 스텁과 페이크는 상태 기반 검증에 주로 쓰인다.
- 상태 기반 검증과 행위 기반 검증은 목적이 다르므로 무엇을 확인하려는지 먼저 정해야 한다.

## 실천 아이템

- [ ] 목을 쓰는 테스트에서 검증하려는 것이 상태인지 행위인지 먼저 정한다.
- [ ] 목이 많아 테스트가 구현 방식에 묶여 있는 곳을 찾아 페이크로 바꿀 수 있는지 본다.

## 용어

테스트 대역 (test double)
: 테스트를 위해 진짜 대신 세우는 가짜 객체나 컴포넌트.

더미 (dummy)
: 전달되기만 하고 실제로 쓰이지 않는 대역.

스텁 (stub)
: 미리 정해진 값을 돌려주는 대역.

페이크 (fake)
: 동작하는 단순 구현을 가진 대역. 인메모리 저장소가 예다.

목 (mock)
: 호출을 기대하고 그 호출 여부를 검증하는 대역. 행위 기반 검증에 쓰인다.

스파이 (spy)
: 호출 기록을 남겨 나중에 확인할 수 있게 하는 대역.

상태 기반 검증
: 실행 후의 상태가 기댓값과 같은지 확인하는 방식.

행위 기반 검증
: 어떤 호출이 일어났는지로 확인하는 방식.
