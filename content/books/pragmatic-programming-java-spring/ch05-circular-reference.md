## 핵심 아이디어

순환 참조는 접근 경로를 늘린다. 경로가 많다는 것은 언뜻 좋게 들리지만 실제로는 시스템
복잡도가 폭발한다는 뜻이다. JPA의 양방향 매핑처럼 편의로 보이는 것이 대표적인 사례이고,
설계에서 가장 자주 보이는 안티패턴 중 하나다.

## 요점

- 순환 참조는 두 개 이상의 객체나 컴포넌트가 서로를 참조해 의존 관계에 사이클이 생긴 상태다.
- 접근 경로가 많아지는 것은 장점처럼 보이지만 복잡도를 키운다.
- 문제는 두 가지다. 무한 루프와 시스템 복잡도.
- 해결책은 네 가지다. 불필요한 참조 제거, 간접 참조 활용, 공통 컴포넌트 분리, 이벤트 기반 시스템 사용.
- 양방향 매핑은 대표적인 순환 참조 사례다. 상위 수준에서도 순환 참조가 생길 수 있다.

## 실천 아이템

- [ ] 양방향 매핑을 쓰기 전에 단방향으로 충분한지 먼저 확인한다.
- [ ] 순환 참조를 발견하면 네 가지 해결책 중 어느 것이 맞는지 따져보고 고친다.

## 용어

순환 참조 (circular reference)
: 두 개 이상의 객체가 서로를 참조해 의존 관계에 사이클이 생긴 상태.

양방향 매핑
: 두 엔티티가 서로를 참조하도록 매핑하는 것. 순환 참조의 대표 사례다.

간접 참조
: 직접 참조를 끊고 식별자나 중간 매개체를 통해 접근하게 만드는 방법.
