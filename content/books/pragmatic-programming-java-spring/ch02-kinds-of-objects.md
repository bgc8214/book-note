## 핵심 아이디어

VO, DTO, DAO, 엔티티는 저연차 때 외운 정의가 시간이 갈수록 혼란이 되는 대표적인 용어들이다.
특히 엔티티는 JPA에서 만들어진 용어가 아니다. JPA의 엔티티는 엔티티라는 개념을 표현하는
수단 하나일 뿐이어서, 둘을 묶어 암기하면 나중에 설명되지 않는 말들을 만나게 된다.

## 요점

- VO는 "쓰기가 불가한 읽기 전용 객체"가 아니다. 불변성, 동등성, 자가 검증 세 조건을 갖춘 객체다.
- 엔티티라는 개념은 JPA가 없던 시절부터 있었다. JPA 엔티티는 그 개념의 구현 수단 하나다.
- 도메인 모델의 엔티티와 DB 관계형 모델의 엔티티는 같은 것이 아니다.
- 엔티티를 "JPA 엔티티"로 암기하면 처음에는 쉽지만 시간이 지날수록 혼란만 커진다.

## 실천 아이템

- [ ] VO를 만들 때 불변성·동등성·자가 검증 세 조건을 실제로 충족하는지 확인한다.
- [ ] 도메인 엔티티와 JPA 엔티티를 한 클래스로 쓸지 나눌지 의식적으로 결정하고 기록한다.

## 용어

VO (Value Object)
: 값 객체. 불변성, 동등성, 자가 검증을 갖춘 객체다. 읽기 전용이라는 설명만으로는 부족하다.

DTO (Data Transfer Object)
: 데이터 전송 객체. 계층이나 경계를 넘길 목적으로 데이터를 담는 객체.

DAO (Data Access Object)
: 데이터 접근 객체. 데이터 저장소 접근을 담당하는 객체.

불변성
: 생성 후 상태가 바뀌지 않는 성질. VO의 조건 하나.

동등성
: 식별자가 아니라 값이 같으면 같은 객체로 취급하는 성질. VO의 조건 하나.

자가 검증
: 객체가 스스로 유효성을 보장하는 성질. 잘못된 상태의 객체가 만들어지지 않게 한다.

도메인 엔티티
: 도메인 모델에서 식별자를 갖고 생애주기를 가지는 객체. JPA 엔티티와 같은 것이 아니다.
