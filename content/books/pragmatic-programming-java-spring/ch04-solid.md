## 핵심 아이디어

SOLID의 목표는 유지보수성과 확장성이고, 다섯 원칙을 관통하는 것은 의존성이다. 그런데
스프링이 의존성 주입을 대신 해주기 때문에 많은 개발자가 의존성 주입과 의존성 역전을
같은 것으로 여긴다. 둘은 다르다. 주입은 받아오는 것이고 역전은 방향을 뒤집는 것이다.

## 요점

- SOLID는 로버트 C. 마틴이 고안한 다섯 원칙이고, 각 원칙의 목표는 소프트웨어의 유지보수성과 확장성이다.
- 의존성 주입과 의존성 역전은 다른 개념이다. 스프링이 주입을 해준다고 역전이 이뤄지는 것은 아니다.
- 의존성이 강조되는 이유는 구조적 문제 대부분이 의존 관계에서 생기기 때문이다.
- 원칙을 암기하면 이름만 남고 왜 그래야 하는지는 남지 않는다.
- 유지보수는 사람이 하는 일이므로, 원칙의 판단 기준도 결국 사람이 코드를 이해할 수 있는지에 놓인다.

## 실천 아이템

- [ ] 구현체가 하나뿐인 인터페이스를 만들 때 굳이 분리하는 이유를 한 줄로 적어둔다.
- [ ] 의존성 주입은 하고 있지만 의존성 역전은 못 하고 있는 지점을 코드에서 찾는다.

## 용어

단일 책임 원칙 (SRP)
: 하나의 모듈이 하나의 책임만 갖게 하는 원칙.

개방 폐쇄 원칙 (OCP)
: 확장에는 열려 있고 변경에는 닫혀 있게 만드는 원칙.

리스코프 치환 원칙 (LSP)
: 하위 타입은 상위 타입을 대체할 수 있어야 한다는 원칙.

인터페이스 분리 원칙 (ISP)
: 쓰지 않는 메서드에 의존하지 않도록 인터페이스를 나누는 원칙.

의존성 역전 원칙 (DIP)
: 고수준 모듈이 저수준 모듈에 의존하지 않도록 의존 방향을 뒤집는 원칙.

의존성 주입 (DI)
: 필요한 의존 객체를 외부에서 받아오는 기법. 의존성 역전과 같은 것이 아니다.
