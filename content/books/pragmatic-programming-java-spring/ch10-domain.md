## 핵심 아이디어

애플리케이션의 본질은 스프링이나 JPA가 아니라 도메인이다. 그래서 애플리케이션을 개발한다는
말은 도메인을 개발한다는 말과 같다. 1부와 2부에서 틈틈이 흘려온 이야기가 여기서 한 문장으로
모인다.

## 요점

- 소프트웨어 공학에서 도메인은 애플리케이션이 해결하려는 문제 영역을 뜻한다.
- 애플리케이션의 본질은 스프링이나 JPA가 아니라 도메인이다.
- 도메인 모델과 영속성 객체는 통합할 수도 있고 구분할 수도 있다.
- 통합 전략은 단순하지만 도메인이 영속성에 끌려가고, 구분 전략은 깨끗하지만 변환 비용이 든다.

## 실천 아이템

- [ ] 도메인 모델과 영속성 객체를 통합할지 구분할지 프로젝트 단위로 결정하고 기록한다.
- [ ] 새 요구사항을 받으면 도메인 용어로 먼저 적고 그다음 기술 용어로 옮긴다.

## 용어

도메인 (domain)
: 애플리케이션이 해결하고자 하는 문제 영역.

영속성 객체
: 저장소에 저장되고 불러와지는 형태의 객체. 도메인 모델과 같을 필요는 없다.
