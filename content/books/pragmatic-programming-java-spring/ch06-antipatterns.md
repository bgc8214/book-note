## 핵심 아이디어

개발에 정답은 없지만 "이렇게 만들면 유지보수와 확장 관점에서 좋지 못하다"고 알려진
안티패턴은 있다. 이 장이 모은 것은 스프링 개발자가 많이 저지르는 구조적 실수들이고,
전부 기초적이면서 누구나 한 번쯤 해본 것들이다.

## 요점

- 스마트 UI는 에릭 에반스의 『도메인 주도 설계』에서 소개되며 유명해진 안티패턴이다.
- 양방향 레이어드 아키텍처는 레이어 간 참조가 양쪽으로 흘러 레이어를 나눈 의미를 잃는다.
- 레이어별로 모델을 따로 두는 구성과 공통 모듈로 묶는 구성 각각에 문제가 있다.
- 트랜잭션 스크립트는 서비스가 모든 로직을 들고 도메인에는 데이터만 남는 형태다.
- 서비스의 역할은 도메인 객체나 도메인 서비스에 일을 위임하는 공간이어야 한다.

## 실천 아이템

- [ ] 내 서비스 코드가 트랜잭션 스크립트인지 확인한다. 도메인 객체가 데이터만 들고 있으면 그렇다.
- [ ] 레이어 간 참조가 한 방향으로만 흐르는지 확인한다.

## 용어

스마트 UI
: UI 계층에 비즈니스 로직이 모이는 안티패턴. 『도메인 주도 설계』에서 소개됐다.

양방향 레이어드 아키텍처
: 레이어 간 참조가 양방향으로 흐르는 상태. 레이어 구분의 의미가 사라진다.

트랜잭션 스크립트
: 서비스가 절차적으로 모든 로직을 수행하고 도메인은 데이터 컨테이너로 남는 형태.

## 연결

- 위임하는 공간으로서의 서비스는 [7장 서비스](/books/pragmatic-programming-java-spring/service/) 에서 본격적으로 다룬다.
