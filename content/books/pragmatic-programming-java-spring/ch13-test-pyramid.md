## 핵심 아이디어

테스트 피라미드의 축은 개수나 중요도가 아니라 **실제 사용자의 사용 사례와 얼마나 가까운지**다.
위로 갈수록 실제 환경에 가까워지고, 그 대가로 느려지고 비싸진다. 그래서 꼭대기를 E2E가
아니라 UI 테스트나 CI 테스트로 표기하기도 한다.

## 요점

- 가장 대중적인 분류 체계는 단위 테스트, 통합 테스트, E2E 테스트의 3단 구조다.
- 피라미드의 축은 테스트가 실제 사용자의 사용 사례와 얼마나 가까운지를 나타낸다.
- 위쪽에 위치할수록 실제 사용자 환경에 가까운 테스트다.
- 꼭대기를 E2E 테스트가 아니라 UI 테스트나 CI 테스트로 표기하는 경우도 있다.

## 실천 아이템

- [ ] 우리 프로젝트의 테스트가 피라미드의 어디에 몰려 있는지 세어본다.
- [ ] 느린 상위 테스트 중 아래 단계로 내릴 수 있는 것을 찾아 옮긴다.

## 용어

단위 테스트 (unit test)
: 작은 단위를 격리해 검증하는 테스트. 피라미드의 바닥이다.

통합 테스트 (integration test)
: 여러 구성 요소를 함께 놓고 검증하는 테스트.

E2E 테스트 (end-to-end test)
: 사용자 관점에서 전체 흐름을 검증하는 테스트. 실제 환경에 가장 가깝고 가장 비싸다.
