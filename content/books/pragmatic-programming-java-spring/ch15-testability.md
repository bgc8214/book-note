## 핵심 아이디어

테스트를 "개발이 끝난 뒤 추가하는 검증 수단"으로만 보면 테스트의 절반을 놓친다. 테스트는
품질을 보증할 뿐 아니라 설계를 개선한다. 테스트하기 어렵다는 것은 테스트 기법이 부족하다는
신호가 아니라 설계가 나쁘다는 신호다.

## 요점

- 테스트의 이점은 회귀 버그 방지만이 아니다. 전체 시스템의 품질을 끌어올린다.
- 테스트를 개발 완료 후 작성하는 것으로만 보면 그 효과를 얻을 수 없다.
- 테스트를 어렵게 만드는 대표 요소는 숨겨진 입력과 숨겨진 출력이다.
- 테스트하기 어려운 코드를 만나면 테스트 방법을 찾기보다 설계를 의심해야 한다.

## 실천 아이템

- [ ] 테스트하기 어려운 코드를 만나면 먼저 설계를 의심하고 고칠 지점을 찾는다.
- [ ] 현재 시각, 랜덤, 전역 상태처럼 숨겨진 입력을 파라미터로 드러낸다.

## 용어

테스트 가능성 (testability)
: 코드를 테스트하기 쉬운 정도. 설계 품질의 지표로 쓸 수 있다.

숨겨진 입력
: 파라미터로 드러나지 않은 채 결과에 영향을 주는 값. 현재 시각, 랜덤, 전역 상태 등.

숨겨진 출력
: 반환값으로 드러나지 않는 부수 효과.
